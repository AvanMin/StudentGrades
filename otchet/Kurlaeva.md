3. **Разработка модели оценки (`Grade.kt`):**
    * Создан Kotlin-класс `Grade` в пакете `data/model`.
    * Добавлены поля `id`, `disciplineId`, `value`, `date`, `workType` и `comment`.
    * Предусмотрена возможность связывать каждую оценку с соответствующей дисциплиной через `disciplineId`.
    * Комментарий сделан необязательным.

4. **Организация структуры данных проекта:**
    * Модели данных размещены в отдельном пакете `data/model`.
    * Сохранено разделение моделей данных и пользовательского интерфейса на отдельные пакеты.
    * Подготовлена основа для дальнейшего подключения локальной базы данных и реализации операций с записями.

5. **Проверка соответствия моделей требованиям проекта:**
    * Сверены названия и назначение полей моделей с требованиями технического задания.

**Название спринта:** «Расчёт среднего балла и аналитика»

**Цель спринта:** Определение требований к функциям расчёта среднего балла, фильтрации и сортировки оценок, а также отображению динамики успеваемости. Контроль соответствия разрабатываемого функционала пользовательским сценариям и критериям приёмки.

## 1. Выполненные задачи Product Owner

1. **Анализ текущих требований проекта:**
   - Изучены пользовательские истории `US-01` — `US-11` из `User_stories.md`.
   - Уточнены требования к отображению общего среднего балла и среднего балла по каждой дисциплине.
   - Учтены правила расчёта среднего арифметического: сумма оценок делится на количество оценок, результат отображается с точностью до сотых.
   - Зафиксировано требование корректной обработки ситуации, когда оценки отсутствуют: вместо некорректного значения должно отображаться `—`.

2. **Формирование задач спринта и приоритетов:**
   - Расчёт среднего балла по отдельным дисциплинам.
   - Расчёт общего среднего балла по всем имеющимся оценкам.
   - Отображение количества оценок.
   - Реализация фильтрации оценок по дисциплине, периоду и типу работы.
   - Реализация сортировки оценок по дате и значению.
   - Отображение динамики среднего балла по периодам.

3. **Подготовка критериев приёмки:**
   - Средний балл рассчитывается как среднее арифметическое всех оценок.
   - Результат расчёта округляется и отображается до двух знаков после запятой.
   - После добавления, изменения или удаления оценки средние значения должны обновляться с учётом актуальных данных.
   - При отсутствии оценок приложение отображает `—` и не выполняет деление на ноль.
   - Фильтры и сортировка должны изменять отображаемый список в соответствии с выбранными параметрами.
   - Экран динамики должен показывать изменение среднего балла по временным периодам.

4. **Согласование требований с командой:**
   - Сформирован перечень функциональных задач для Lead Developer.
   - Определены ожидаемые результаты спринта и условия, по которым можно принимать готовые функции.
   - Учтено разделение ответственности между Product Owner, Lead Developer и QA / DevOps.
